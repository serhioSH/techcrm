================================================================================
1. DESCRIPCION GENERAL
================================================================================

TECHCRM-POS es un sistema punto de venta (POS) diseñado para restaurantes y 
establecimientos de comida rápida. Permite:

- Gestión de mesas y pedidos
- Control de inventario de productos
- Procesamiento de pagos/cobros
- Reportes de ventas y movimientos
- Gestión de usuarios con permisos
- Impresión térmica de tickets
- Sistema de cajas y cierre diario
- Actualizaciones automáticas desde GitHub

El sistema está desarrollado con Python 3.12, PySide6 (Qt para Python), 
SQLite y es compilado a ejecutable con PyInstaller para distribución.

5. COMPONENTES PRINCIPALES
================================================================================

MAIN.PY
-------
- Punto de entrada de la aplicación
- Inicializa base de datos
- Muestra pantalla de login
- Conecta señales para actualización automática
- Manejo de excepciones global

MAIN_WINDOW.PY (Ventana Principal)
----------------------------------
Responsable de:
- Interfaz principal después del login
- Menú de navegación lateral
- Carga dinámica de pantallas
- Gestión de sesión del usuario
- Barra de estado

Flujo de Carga de Pantallas:
1. Usuario hace clic en botón (ej: "Mesas")
2. main_window.py importa dinámicamente: app.ui.screens.mesas_screen
3. Crea instancia de MesasScreen
4. Reemplaza el contenido central
5. Pantalla comienza a funcionar

LOGIN_WINDOW.PY
---------------
- Autenticación de usuario
- Validación de credenciales
- Conexión con auth_service.py
- Gestión de sesión

SCREENS (Pantallas Especializadas)
----------------------------------
Cada pantalla hereda de _base_screen.py y proporciona:

- Interfaz para una función específica (mesas, productos, etc)
- Tabla/lista de datos con botones
- Diálogos para crear/editar/eliminar
- Validación de datos
- Comunicación con servicios

Ejemplo: mesas_screen.py
- Muestra tabla de mesas
- Botones: Crear, Editar, Eliminar, Seleccionar
- Diálogo para crear nueva mesa
- Al guardar, llama mesa_service.create_mesa()

6. SERVICIOS CLAVE

USUARIO_SERVICE.PY
------------------
Operaciones:

----------------

7. BASE DE DATOS
================================================================================

ESQUEMA PRINCIPAL
-----------------

USUARIOS
--------
CREATE TABLE usuarios (
    id INTEGER PRIMARY KEY,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    nombre TEXT NOT NULL,
    rol TEXT NOT NULL,  -- admin, cajero, mesero, cocina
    activo BOOLEAN DEFAULT 1,
    fecha_creacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)

PRODUCTOS
---------
CREATE TABLE productos (
    id INTEGER PRIMARY KEY,
    nombre TEXT NOT NULL UNIQUE,
    descripcion TEXT,
    precio_venta DECIMAL(10,2) NOT NULL,
    precio_costo DECIMAL(10,2),
    stock INTEGER DEFAULT 0,
    categoria TEXT,
    activo BOOLEAN DEFAULT 1
)

VENTAS
------
CREATE TABLE ventas (
    id INTEGER PRIMARY KEY,
    mesa_id INTEGER,
    usuario_id INTEGER,
    fecha TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    total DECIMAL(10,2),
    estado TEXT,  -- pendiente, pagada, cancelada
    FOREIGN KEY(mesa_id) REFERENCES mesas(id),
    FOREIGN KEY(usuario_id) REFERENCES usuarios(id)
)

VENTA_ITEMS
-----------
CREATE TABLE venta_items (
    id INTEGER PRIMARY KEY,
    venta_id INTEGER,
    producto_id INTEGER,
    cantidad INTEGER,
    precio_unitario DECIMAL(10,2),
    subtotal DECIMAL(10,2),
    FOREIGN KEY(venta_id) REFERENCES ventas(id),
    FOREIGN KEY(producto_id) REFERENCES productos(id)
)

MESAS
-----
CREATE TABLE mesas (
    id INTEGER PRIMARY KEY,
    numero INTEGER UNIQUE,
    zona TEXT,
    capacidad INTEGER,
    estado TEXT DEFAULT 'disponible'  -- disponible, ocupada, pagando
)

CAJAS
-----
CREATE TABLE cajas (
    id INTEGER PRIMARY KEY,
    fecha_apertura TIMESTAMP,
    fecha_cierre TIMESTAMP,
    monto_inicial DECIMAL(10,2),
    usuario_id INTEGER,
    estado TEXT DEFAULT 'abierta',  -- abierta, cerrada
    FOREIGN KEY(usuario_id) REFERENCES usuarios(id)
)

CAJA_MOVIMIENTOS
----------------
CREATE TABLE caja_movimientos (
    id INTEGER PRIMARY KEY,
    caja_id INTEGER,
    tipo TEXT,  -- ingreso, egreso, venta
    descripcion TEXT,
    monto DECIMAL(10,2),
    fecha TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(caja_id) REFERENCES cajas(id)
)

9. SISTEMA DE ACTUALIZACIONES
================================================================================

VERSIONING
----------
La versión actual está en: version.json

{
  "version": "1.0.1",
  "download_url": "https://github.com/serhioSH/techcrm/releases/download/v1.0.1/TECHCRM-POS.exe",
  "release_date": "2026-09-23",
  "description": "Bug fixes y mejoras"
}

VERIFICACION AUTOMATICA
-----------------------
1. Al iniciar la app, se ejecuta updater.py
2. Lee version.json local
3. Conecta con GitHub y obtiene version.json remoto
4. Compara versiones: local vs remoto
5. Si hay versión más nueva:
   - Muestra diálogo: "Actualización disponible"
   - Si usuario elige "Sí":
     a. Descarga el .exe nuevo
     b. Lo guarda en carpeta temp
     c. Ejecuta batch script que:
        - Cierra app actual
        - Reemplaza .exe antiguo con nuevo
        - Ejecuta app nueva

ARCHIVOS RELACIONADOS
---------------------
- updater.py - Lógica de actualización
- version.json - Versión actual
- update_helper.bat - Script para reemplazar archivo

CONFIGURACION
-------------
En Configuración → Admin, el usuario técnico puede:
- Cambiar URL de versión.json en GitHub
- Forzar verificación de actualización

PERSISTENCIA
-----------
La URL se guarda en: %LOCALAPPDATA%\TECHCRM\config.json
Usando ConfigManager para persistencia entre sesiones

11. TROUBLESHOOTING
================================================================================

PROBLEMA: "ModuleNotFoundError: No module named 'app.ui.screens'"
------------------------------------------------------------------
SOLUCION:
- Asegúrate que app/ui/screens/ tiene __init__.py
- Verifica main.spec incluye 'app.ui.screens' en hiddenimports
- Recompila: pyinstaller main.spec --clean

PROBLEMA: Base de datos corrupta
---------------------------------
SOLUCION:
- Elimina crm_system.db de %LOCALAPPDATA%\TECHCRM\
- Al reiniciar, la app recrea la DB desde migrations.py
- Alterna: restaurar desde backup en backups/

PROBLEMA: Impresora no imprime
-------------------------------
SOLUCION:
- Verifica que la impresora está conectada
- En Configuración, verifica que está seleccionada
- Prueba con comando de prueba en printer_manager.py

PROBLEMA: Cambios en código no aparecen en .exe compilado
----------------------------------------------------------
SOLUCION:
- Asegúrate de haber hecho: git add . && git push
- Recompila: pyinstaller main.spec --clean
- Espera a que termine (puede tomar 1-2 minutos)
- Prueba el nuevo .exe

PROBLEMA: Usuarios no ven actualización disponible
---------------------------------------------------------
SOLUCION:
- Verifica que version.json está en GitHub (rama main)
- En navegador: https://raw.githubusercontent.com/.../version.json
- Debe devolver JSON (no error 404)
- En app, ve a Configuración y verifica URL de actualización
- Espera 5-10 minutos (caché de GitHub)

PROBLEMA: App se cuelga al cargar pantalla
-------------------------------------------
SOLUCION:
- Mira logs: %LOCALAPPDATA%\TECHCRM\logs\app.log
- Busca errores cerca de la carga
- Verifica que servicio correspondiente no tiene errores
- Prueba mode desarrollo: python main.py
